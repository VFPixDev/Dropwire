# Аудит Dropwire — 12 ноября 2026

Уточнение: этот документ описывает первый, целевой проход по трём жалобам
и связанным с ними путям. Называть его полным аудитом было неточно.
Последующий систематический проход описан в [SYSTEM-AUDIT-2026-11-12.md](SYSTEM-AUDIT-2026-11-12.md).

Проверены загрузка и разбор публикаций, перевод, обычные и inline-карточки,
медиакэш, настройки, обработка нескольких ссылок, очередь скачивания,
подписанные ссылки, зависимости и Docker-сборка.

## Исправленные причины трёх жалоб

| Проблема | Причина | Исправление |
| --- | --- | --- |
| Вместо перевода появляется сообщение DeepL | FxTwitter возвращал уведомление переводчика в поле успешного перевода; содержимое не проверялось | Проверка JSON, HTML и отображаемого перевода, в том числе цитат. При сбое сохраняется оригинал без ложной пометки о переводе. Ошибка локализованного запроса не уничтожает успешно полученный оригинал |
| Иногда возвращается старое оформление | Отказ Rich Message включал старую отправку текста/альбома и отдельного сообщения «👆» с кнопкой; существовал отдельный старый inline-путь | Удалены оба старых пути и старый форматтер. При отказе медиа повторяются загрузка файлов и отправка Rich Message без медиа. Полный отказ Rich API оставляет короткое сообщение со ссылкой |
| При недоступном медиа нет ссылки | Ошибочные ветки старой отправки забывали клавиатуру; один неудачный файл отменял подготовку всех вложений | Остальные вложения сохраняются на своих местах. Rich Message содержит уведомление о недоступном медиа и кнопку оригинала. При ошибке получения/отправки публикации также есть кнопка |

Ошибка DeepL зависит от ответа внешнего сервиса для конкретной публикации.
Сбой в одном топике при работающем переводе другой публикации сам по себе
не означает отдельную неисправность топика. Живой запрос перевода во время
аудита выполнился успешно; точное состояние сервиса в момент скриншота
без производственных логов восстановить нельзя.

## Дополнительные исправления

- Значение перевода `off` теперь отличается от отсутствующей настройки и прекращает наследование языка.
- Коды языка вроде `en` отображаются как «английского». Название группы экранируется в меню перевода.
- Исходное сообщение в группе удаляется только после успешной обработки всех найденных ссылок. Ошибка, отключённый провайдер, превышение лимита и неоднозначный сетевой результат сохраняют исходник.
- Ссылки обрабатываются и в подписях к медиа. Упоминание бота распознаётся без учёта регистра.
- Сбой одной ссылки не прерывает обработку следующих. Уведомление о лимите отправляется в исходный топик.
- Неиспользуемые блокировки обработки не накапливаются в памяти.
- Отмена задания до запуска или во время ожидания больше не блокирует очередь скачивания.
- Одинаковая цитата/родитель учитывается один раз при сохранении Telegram file_id. Недоступность медиакэша не блокирует обычную карточку.
- Не-ASCII токен скачивания обрабатывается как ошибка валидации вместо HTTP 500.
- Пустая HTML-страница провайдера не превращается в пустой твит. Текст ошибок провайдера экранируется перед HTML-отправкой.
- Pillow обновлён с 12.3.0 до 13.0.0 после обнаружения известных уязвимостей. Исправлен устаревший вызов функции в `scripts/smoke_rich.py`.

## Границы проверки

Тестовые сообщения пользователям и в рабочие чаты не отправлялись.
Проверки Telegram-ответов выполнялись с имитацией API, включая отказы медиа,
устаревший кэш и неоднозначный сетевой результат.

Docker Scout потребовал входа в Docker-аккаунт, поэтому проверка CVE
системных пакетов образа этим инструментом не завершена в первом проходе.
В последующем проходе образ проверен Trivy, системные пакеты обновлены,
повторный результат High/Critical — без находок.

Исправления находятся в рабочем дереве и локальном Docker-образе.
Рабочий сервер не обновлялся. Обнаруженные локальные Compose-контейнеры
версии 1.2.0 остановлены с сентября; новый polling-процесс не запускался.
Уже отправленные старые сообщения этими изменениями не редактируются.
